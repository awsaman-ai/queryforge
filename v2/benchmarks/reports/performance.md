## Method

- Every scenario runs against a warm engine assembled once: config, corpus,
  model, index, pipeline. The worker process id is recorded before and after
  each scenario to prove nothing respawned.
- Latency is wall-clock around `pipeline.Run`; per-stage numbers come from
  `pipeline.Stats`, the redacted telemetry, never from parsed output.
- Percentiles are nearest-rank: every reported value is a latency that
  actually occurred. p99 needs 100 samples to be meaningful, p95 needs 20;
  under-sampled values are marked.
- Throughput is completed requests over wall-clock time of the whole batch.
- Scale configs are generated from a reviewed config (the Phase 7 commerce
  schema) with synthetic entities appended; the core schema is byte-identical
  at every scale and the synthetic entities never join to it.
- No network is used on the request path; the embedding worker runs offline
  by default (Phase 8, section 16.11).
